# Архитектура, регламент и правила разработки проекта (AGENTS.md)

> **Назначение документа:**  
> Данный файл является полным архитектурным и регламентным руководством для разработчиков и автономных ИИ-агентов (Google Antigravity, Claude, Cursor, AI Studio, etc.).  
> Он содержит неизменные инженерные стандарты, протокол версионирования, автоматизацию релизов в GitHub и чеклист анти-регрессии.

---

## 1. Спецификация проекта: ProAgent Guide (Git: pro-agent-guide)

- **Продукт:** Интерактивный SPA-справочник вайбкодера и ультимативный хаб ИИ-агентов.
- **Миссия:** Систематизация слеш-команд Google Antigravity, обеспечение 100% кросс-совместимости экосистемы (Antigravity `.agents/` + `AGENTS.md`, Claude Code `.claude/` + `CLAUDE.md`, Codex / Custom Harness), каталог боевых промптов и автоматизаций.
- **Платформа:** Web SPA (Vite + React 19).
- **Стек технологий:** React 19, Vite, Tailwind CSS v4, Lucide React, Neo-Brutalism & Y2K Pop Design System.
- **Дизайн-система:** `DESIGN.md` (NeoBrutalism Studio: холст `#F4F0EA`, 3px hairline borders, hard drop shadows `5px 5px 0px #000`, акценты `#FFE600`, `#FF59B3`, `#38E54D`, `#00F0FF`, поддержка Dark & Light тем по WCAG AA).

## 3. Фундаментальные инженерные принципы (SOLID, DRY, KISS, YAGNI)

Любое изменение в коде обязано строго соблюдать 4 принципа:

### 3.1. Изоляция модулей (Module Isolation & Fault Tolerance)
- Каждый функциональный модуль/блок обязан быть **самодостаточным и изолированным**.
- Любая внутренняя ошибка или сбой сети/стороннего сервиса обязаны перехватываться (`try/catch`) внутри модуля.
- **Сбой в одном второстепенном блоке никогда не должен приводить к падению всего приложения или белому экрану (Zero Crash / Graceful Degradation).**

### 3.2. Принципы SOLID
1. **S — Single Responsibility (Единственная ответственность):**  
   Один файл / класс / функция решает строго одну задачу (хранилище, UI-компонент, клиент API, алгоритм).
2. **O — Open/Closed (Открытость для расширения, закрытость для модификации):**  
   Новые фичи добавляются созданием новых модулей/плагинов/адаптеров, а не бесконечным раздуванием старых switch-case.
3. **L — Liskov Substitution (Подстановка Лисков):**  
   Абстракции и адаптеры (например, адаптеры хранилищ или AI-провайдеров) взаимозаменяемы без переписывания потребителей.
4. **I — Interface Segregation (Разделение интерфейсов):**  
   Компоненты не зависят от избыточных интерфейсов; передаются только те свойства и колбэки, которые нужны.
5. **D — Dependency Inversion (Инверсия зависимостей):**  
   Высокоуровневая бизнес-логика зависит от абстракций (интерфейсов), а не от низкоуровневых хаков или конкретных SDK.

### 3.3. Принцип DRY (Don't Repeat Yourself)
- Общие математические, строковые и форматирующие функции выносятся в утилиты.
- Дизайн-токены (цвета, шрифты, радиусы) централизуются в одном файле темы через CSS-переменные или токены дизайн-системы.

### 3.4. Принцип KISS & YAGNI
- Предпочитать простые, прозрачные решения без лишних слоев косвенности.
- Не подключать тяжелые библиотеки ради двух функций, которые пишутся на чистом стандартном API в 10 строк.

## 4. Модель данных и безопасность (Strict Whitelist & Secrets)

1. **Белый список полей (Whitelist Policy):**
   - При отправке данных на бэкенд или сторонние API передавать **СТРОГО** поля из утвержденного белого списка. Запрещено прокидывать «сырые» объекты целиком со служебными ключами.
2. **Безопасность ключей и переменных окружения:**
   - **СТРОГИЙ ЗАПРЕТ** на хардкод паролей, секретных токенов и боевых API-ключей в исходном коде.
   - Все секреты читаются строго через переменные окружения (`.env`).
   - Файл `.env` обязан быть добавлен в `.gitignore`. В репозиторий коммитится только безопасный образец `.env.example`.

## 5. Стандарты UI/UX и поддержка тем (Dark & Light Theme Standards)

1. **Поддержка двух тем (Dark & Light) с первого дня:**
   - Все элементы интерфейса обязаны проектироваться с поддержкой светлой и тёмной темы.
   - Использование CSS-переменных:
     - `--bg-canvas`, `--bg-card`, `--bg-muted`, `--text-main`, `--text-muted`, `--border-main`, `--shadow-main`, `--primary`.
2. **Строгие требования контрастности (WCAG AA):**
   - **Запрет белого текста на светлом фоне и невидимого серого текста на тёмном фоне.**
   - Контрастность основного текста обязана быть не менее **4.5:1**, для заголовков — не менее **7:1**.
3. **Эргономика интерактивных элементов:**
   - Для мобильных и сенсорных экранов минимальный физический размер интерактивной области — **44 × 44 px**.
   - Обязательная поддержка мобильных безопасных зон (`env(safe-area-inset-*)`).

## 6. Централизованное версионирование и автоматизация релизов в GitHub

Проект использует строгий регламент управления версиями (SemVer) и непрерывной автоматизации:

### 6.1. Единый источник истины по версии
- Номер версии хранится **строго в одном месте**: `version.json` в корне проекта (`MAJOR.MINOR.PATCH`).
- Все остальные файлы (`package.json`, мобильные манифесты, манифесты расширений) обновляются автоматически скриптом:
  ```bash
  npm run sync-version
  ```

### 6.2. Официальный журнал изменений (`CHANGELOG.md`)
- Любое изменение функционала, фикс или рефакторинг фиксируется в `CHANGELOG.md` по стандарту **Keep a Changelog**:
  - `Added` (новые возможности)
  - `Changed` (изменения существующего функционала)
  - `Fixed` (исправления багов)
  - `Security` (безопасность)

### 6.3. Автоматизированная процедура релиза в 1 клик
Для формирования нового релиза используется команда:
```bash
# Локальный релиз: валидация -> синхронизация -> сборка dist/*.zip -> git commit -> git tag
npm run release

# Полный релиз с автоматической отправкой в GitHub:
npm run release -- --push
```
- При пуше тега `v*.*.*` автоматически срабатывает **GitHub Actions workflow** (`.github/workflows/release.yml`), который создает официальный **GitHub Release** и прикрепляет готовый ZIP-архив дистрибутива.

## 7. Памятка для ИИ-агентов (Anti-Regression Checklist)

Перед завершением любой задачи автономный AI-агент обязан провести самопроверку:
1.  **Точечные правки:** Изменения затронули строго целевые модули, без каскадного расползания правок.
2.  **Защита от падений:** Все рискованные вызовы (сеть, парсинг, сторонние API) защищены блоками `try/catch`.
3.  **Безопасность секретов:** Никакие токены, ключи или пароли не захардкожены в коде.
4.  **Контрастность тем:** Проверено корректное отображение как в тёмной, так и в светлой теме (нет белого на белом / блеклого серого).
5.  **Тесты и валидация:** Скрипт `npm run check-all` завершился с кодом 0 (ALL CHECKS PASSED).
6.  **Сборка:** Команда `npm run build` завершилась с нулем ошибок.
7.  **Синхронность версий:** При изменении версии обновлен `version.json`, запущен `npm run sync-version` и добавлена запись в `CHANGELOG.md`.
